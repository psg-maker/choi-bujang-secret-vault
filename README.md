Supabase의 **SQL Editor → New query**에 SQL 전체를 붙여 넣고 **Run**을 누릅니다. 새 `public.training_notes` 테이블을 만들며, 기존 동명 테이블이 있으면 덮어쓰지 않고 실패합니다. `owner_id`는 nullable `uuid`이며 외래키가 없습니다. RLS를 켜고 `PUBLIC`·`anon`·`authenticated`의 모든 테이블 권한을 회수하며 허용 정책은 만들지 않습니다. 실제 키 입력은 필요하지 않습니다.

마지막 확인 쿼리의 예상 결과는 `note_count=4`, `unassigned_count=4`, `owner_id_type=uuid`, `rls_enabled=true`, `foreign_key_count=0`, `policy_count=0`, 두 `can_select=false`입니다. **Table Editor → training_notes**에서도 `owner_id`와 RLS를 확인하세요. 관리자 SQL Editor에서 자료를 볼 수 있는 것은 정상이며, `anon`·`authenticated`의 읽기는 거부되어야 합니다.

로컬 정적 빌드 확인 명령: `npm.cmd run build -- --local` (PowerShell). 이 명령은 서버 함수를 실행하지 않습니다. 새 정적 출력에는 메모 문장과 키가 없어야 합니다. SQL 실행과 환경변수 설정 후 재배포하고 `/`에서 네 카드, `/api/notes`에서 네 자료, `/data.json`에서 404와 메모 부재, `/aleph.json`에서 현재 단계 2를 확인하세요. GET 이외의 함수 요청은 405로 거부합니다. 설정 누락은 503, DB 조회 실패는 502와 고정 오류 코드만 반환해야 합니다. Supabase에 대한 공개 키 요청의 차단은 심판이 확인하며, 로컬 모의 시험을 그 판정으로 보고하지 않습니다. 과거 Git 커밋과 이전 배포에는 1단계 공개 자료가 남습니다. DB 실행·원격 반영·실제 배포 점검의 확인 범위는 위 날짜별 기록을 따릅니다.

## 메모 문장 검색 절차와 결과 기록

확인 기준은 로컬 전용 SQL에 보존한 가상 메모 본문 네 문장입니다. 문장을 이 README·작업 로그·제출 묶음에 복사하지 말고, 결과에는 검사 시각(KST), URL 또는 커밋 SHA, 검사 범위, 문장별 일치 수, 일치 파일 경로만 적습니다. 네 문장은 순서대로 메모 1~4로 표기합니다. 검색 실패·접속 오류·검사하지 않은 범위는 `미확인`으로 남기며 0건으로 쓰지 않습니다.

### 현재 배포의 정적 파일

1. 재배포 후 Vercel **Deployments → 해당 배포 → Visit**에서 실제 배포 URL을 엽니다. 브라우저 개발자 도구 **Network → Disable cache**를 켜고 새로고침합니다. 배포 URL, 배포 시각, `/aleph.json`의 `commit`과 `step`을 기록합니다. 운영 도메인을 사용했다면 실제 배포 URL도 함께 기록합니다.
2. Network에서 문서 `/`와 해당 화면이 불러온 JS·CSS·정적 JSON 등의 **Response**를 확인합니다. 현재 화면의 스크립트는 HTML 안에 있으므로 `/`의 응답 원문도 반드시 검색합니다. 소스맵 등 추가 정적 파일이 제공되면 그것도 검사 범위에 포함합니다. 각 응답 원문에서 메모 1~4의 전체 문장을 하나씩 정확히 검색하고, 파일별 결과를 기록합니다. 화면에 네 카드가 보인다는 사실은 정적 파일 검색 결과를 대신하지 않습니다.
3. `/data.json`을 직접 열어 HTTP 404와 메모 부재를 확인합니다. 오류 페이지나 다른 HTML로 응답한다면 상태와 응답 종류를 그대로 기록합니다. `/aleph.json`도 네 문장이 없는지 확인합니다. 검사 범위는 실제 확인한 파일 목록으로 한정하며, 화면에서 불러오지 않은 파일까지 전부 검사했다고 쓰지 않습니다.
4. `/api/notes` 응답은 아래의 **공개 API 약점**으로 따로 기록합니다. API로 받은 문장이 화면 DOM에 표시되는 것과 정적 파일에 문장이 포함된 것은 구분합니다.

### GitHub 최신 파일

1. GitHub 저장소에서 배포 대상 브랜치(현재 `main`)를 열고 최신 커밋의 전체 SHA를 기록합니다. 로컬 작업 폴더와 로컬 `HEAD`는 GitHub 최신 파일의 증거가 아닙니다. `/aleph.json`의 SHA와 다르면 차이를 먼저 기록하고, GitHub 최신 SHA와 배포 SHA를 각각 확인합니다.
2. 해당 SHA의 파일 트리로 이동한 뒤 **Code → Download ZIP**으로 그 커밋의 파일을 내려받아 별도 폴더에 풉니다. ZIP이 선택한 SHA의 자료인지 확인합니다. GitHub 검색 인덱스만으로 0건을 판단하지 않습니다.
3. 다운로드한 폴더를 VS Code로 열어 **Search**에서 정규식을 끄고 대소문자 구분을 켭니다. `Use Exclude Settings and Ignore Files`를 끄고 포함·제외 필터를 비워 숨김 파일을 포함한 전체 파일에서 메모 1~4의 전체 문장을 각각 검색합니다. 일치 수와 파일 경로만 기록합니다. 로컬 SQL이 GitHub 파일에 포함되어 있거나 어느 파일에든 문장이 있으면 발견으로 기록합니다.
4. GitHub 최신 SHA와 실제 배포 SHA 양쪽의 검사 결과가 확인되기 전에는 원격 반영 완료라고 쓰지 않습니다. 커밋·푸시·재배포는 이 문서 작성 작업에서 실행하지 않았습니다.

### 과거 노출 상태

옛 공개 커밋과 옛 배포가 남아 있는 한 **과거 노출은 해소되지 않았습니다**. 최신 파일에서 문장을 지우거나 새 배포의 `/data.json`을 없애도 Git 이력, 과거 배포 URL, 이미 복사된 자료가 사라지는 것은 아닙니다. 이 작업에서는 과거 이력이나 배포를 삭제하지 않았으며, 과거 노출 해소·완전 비공개·방어 성공으로 기록하지 않습니다.

아래는 **1단계 시작 틀의 과거 안내**입니다. 현재 작업에는 위의 2단계 안내를 적용합니다.

이 저장소는 1단계에서 학생 본인이 GitHub 저장소와 Vercel 배포를 만드는 출발점입니다. 포함된 메모 네 건은 가상 자료입니다. 실제 학생 자료, 토큰, 비밀키를 넣지 마세요.

## 학생이 하는 일: 세 걸음

1. GitHub 계정을 만듭니다.
2. 방어전 1단계 카드의 **Deploy** 버튼을 누릅니다. Vercel에 GitHub로 로그인하고, 새 저장소가 **본인 계정의 Public 저장소**인지 확인한 뒤 Deploy를 누릅니다.
3. 배포가 끝나면 화면에 나온 `https://…vercel.app` 주소를 방어전 1단계 카드에 붙여넣고 제출합니다. 저장소 주소나 설정 파일은 적지 않습니다.

배포가 끝나면 `/`에서 점령된 가상 자료실을 볼 수 있습니다. `/data.json`에는 같은 가상 메모가 공개됩니다. 이 공개 상태를 확인하는 것이 1단계의 출발점입니다. 1단계 접수와 심판 판정은 포털에서 확인합니다.

## 시작 틀의 자동 처리

`vercel.json`은 정적 결과물 `public`을 배포합니다. 빌드 명령 `npm run build`는 Vercel이 제공하는 GitHub 저장소 소유자·이름, 커밋 SHA, 배포 URL을 검증하고 `public/aleph.json`을 생성합니다. 이 값이 없으면 빌드가 실패하므로, 성공한 것처럼 빈 주소를 내보내지 않습니다. `aleph.json`의 내용만으로 저장소 소유권이나 방어 성공을 인정하지 않습니다. 심판이 공개 저장소의 실제 커밋과 배포된 자료를 따로 대조해야 합니다.

`aleph.config.json`의 `repoUrl`과 `publicAppUrl`은 이전 제출 묶음 방식의 자리표시자입니다. 1단계에서는 학생이 편집하지 않습니다. 2단계 이후 코딩 도구가 필요한 설정과 보호 기능을 단계별로 작성합니다. `npm run bundle`과 `bundle-notes.json`도 1단계의 세 걸음에는 포함되지 않습니다.

로컬에서 가상 화면만 확인할 때는 `npm run build -- --local`을 사용합니다. 로컬 실행은 Vercel 배포나 심판 접수를 증명하지 않습니다. 저장소의 `src/attack-check.mjs`는 실제 배포가 된 뒤 `/data.json`을 비로그인으로 요청해 공개 가상 메모의 확인 표시를 읽습니다.
